How I work

I'm drawn to problems where the interface and the implementation are the same decision. Good software is the kind your user never has to think about, and getting there means caring about both halves.

01 · Understand

Research, user flows, and asking what problem we're actually solving before touching a canvas or a file.

02 · Prototype

Sketch, wireframe, or spin up a rough build fast. Iteration beats over-planning when you don't yet know what's hard.

03 · Ship & learn

Push to GitHub, pair with teammates, test with real users where I can, and come back with what I learned.
